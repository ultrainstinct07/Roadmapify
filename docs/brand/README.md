# roadmapify brand assets

The route is the build plan. Its milestones are the work and decisions that
survive between sessions. The north star is the goal that gives them direction.

Use **roadmapify** in lowercase for the product and **roadmap** for the command.
The primary description is: **A phased build plan with memory that survives
context loss.** Keep supporting language concrete: goals, phases, decisions,
evidence, and the next task.

## Assets

| Asset | Use |
| --- | --- |
| [logo.png](logo.png) | Navy route and mint milestones, for light backgrounds |
| [logo-dark.png](logo-dark.png) | Ivory route and mint milestones, for dark backgrounds |
| [hero.png](hero.png) | Wide README illustration: plan and memory connected to a goal |

Both logos are transparent 1254 × 1254 PNGs. The hero is a 2172 × 724 PNG.
The README uses a `picture` element to choose the logo for the reader's theme.
Keep the full square logo canvas as clear space; do not stretch, rotate, or add
shadows. Use the hero as an illustration, not as a product screenshot. Keep key
explanations in selectable text outside images for accessibility.

## Palette and typography

These are the intended reference colors; generated artwork includes tonal variation.

| Color | Hex | Role |
| --- | --- | --- |
| Ink | `#102A33` | Dark surfaces and primary text |
| Mint | `#5BE3B0` | Route, milestones, and emphasis |
| Ivory | `#F7F5EE` | Light surfaces and reversed marks |
| Amber | `#E9B45B` | Small highlights in illustrations |

Use native sans-serif typography for headings and prose, and monospace for CLI
examples. The GitHub README uses the reader's native GitHub typography; no font
or image service is required to serve these assets.
